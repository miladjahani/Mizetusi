# استقرار NEXUS روی سرور اختصاصی (VPS)

این راهنما پنل را روی سروری می‌نویسد که **خودتان مالکش هستید**. نتیجه سه چیز است که روی سرویس‌های اشتراکی ندارید:

- **IP اختصاصی** — دامنه‌ی شما فقط روی سرور شماست، پس با ساخته‌شدن یا بن شدن یک سرویس دیگر، آدرس شما هم نمی‌سوزد.
- **TLS با دامنه‌ی خودتان** — دیگر لازم نیست SNI یک دامنه‌ی غریبه (`*.up.railway.app` و…) را جعل کنید؛ کلاینت‌ها به SNI واقعیِ خودتان وصل می‌شوند و قطعی‌های ناشی از فیلترینگ روی SNI حذف می‌شود.
- **عدم امکان بن شدن** — تنها کسی که می‌تواند سرویس را متوقف کند، خود شماست.

زمان کل: حدود ۱۵ دقیقه.

---

## ۱. انتخاب سرور

حداقل مشخصات: **۱ هسته، ۱ گیگابایت رم، ۲۰ گیگابایت دیسک**. برای پنل و سرویس‌های سبک کافی است.

| ارائه‌دهنده | پلن | ماهانه | توضیح |
|---|---|---|---|
| Hetzner | CX22 | ≈ ۴ € | پایدارترین گزینه، پنل کنترل بدون تأیید اضافه |
| OVH | VPS-1 | ≈ ۴.۵ € | گزینه‌ی خوب اروپایی |
| Contabo | Cloud VPS 10 | ≈ ۵ € | ارزان، دیسک بزرگ |

**موقعیت مکانی:** آلمان، هلند، فنلاند یا ترکیه. سرورهای آمریکایی تأخیر بیشتری برای کاربران داخل ایران دارند.

> نکته: بعضی ارائه‌دهنده‌ها آی‌پی ایران را از پنل کنترل مسدود می‌کنند. اگر موقع ساخت سرور به مشکل خوردید، با پشتیبانی‌شان تماس بگیرید؛ خودِ ترافیک سرور معمولاً بدون محدودیت است.

سیستم‌عامل را **Debian 12** یا **Ubuntu 24.04** انتخاب کنید.

---

## ۲. دامنه

یک دامنه‌ی ارزان (سالانه چند دلار) بخرید و یک رکورد **A** بسازید:

```
panel.example.com.   A   <IP سرور>
```

بعد از چند دقیقه `dig panel.example.com` باید IP سرور را نشان دهد.

---

## ۳. نصب

از طریق SSH با کاربر root وصل شوید:

```bash
ssh root@<IP سرور>
```

### ۳.۱ کلید SSH و کاربر غیر-root (توصیه‌شده)

```bash
# روی کامپیوتر خودتان، اگر هنوز کلید ندارید:
ssh-keygen -t ed25519 -C "mizetusi"

# روی سرور:
mkdir -p /root/.ssh && nano /root/.ssh/authorized_keys   # کلید عمومی را اینجا بچسبانید
```

### ۳.۲ فایروال

```bash
apt-get update -qq && apt-get install -y -qq ufw
ufw allow OpenSSH
ufw allow 8080/tcp    # پنل
ufw allow 8443/tcp    # Reality
ufw allow 8446/tcp    # MTProto
ufw allow 8448/tcp    # وب پروکسی HTTP
ufw allow 8449/tcp    # وب پروکسی SOCKS5
ufw enable
```

همین پنج پورت را در **Security Group** ارائه‌دهنده هم باز کنید (اگر دارد).

### ۳.۳ اجرای اسکریپت نصب

```bash
curl -fsSL https://raw.githubusercontent.com/miladjahani/Mizetusi/main/scripts/install-vps.sh \
  | sudo bash -s -- --domain panel.example.com
```

اسکریپت کارهای زیر را انجام می‌دهد:

1. نصب Docker و پلاگین `docker compose`
2. کلون کردن ریپو در `/opt/nexus`
3. ساخت `.env` با **رمز ادمین و کلید JWT تصادفی** (پسورد تولیدشده را همان‌جا چاپ می‌کند و در `.env` ذخیره می‌شود — آن را از دست ندهید)
4. بیلد و بالا آوردن استک
5. چاپ پورت‌های لازم

پایان کار:

```
panel   : http://panel.example.com:8080
reality : panel.example.com:8443
MTProto : panel.example.com:8446
web     : panel.example.com:8448 / :8449
```

با همان `ADMIN_PASSWORD` وارد شوید و **بلافاصله رمز را از داخل پنل عوض کنید**.

## ۴. TLS روی Cloudflare

### ۴.۱ پنل (پورت ۸۰۸۰) — ابر نارنجی

در Cloudflare یک رکورد `proxy` (ابر نارنجی) برای `panel.example.com` بسازید. چون پنل روی پورت ۸۰۸۰ است و Cloudflare همین پورت را پشتیبانی می‌کند، گواهی SSL به‌صورت خودکار صادر می‌شود و دیگر نیازی به باز کردن ۸۰ روی سرور ندارید.

سپس در پنل، آدرس عمومی را روی دامنه‌ی خودتان تنظیم کنید (`PUBLIC_BASE_URL` در `.env`) تا لینک‌های اشتراک و کارت‌ها درست ساخته شوند.

### ۴.۲ پروتکل‌های TCP (Reality / MTProto / وب) — ابر خاکستری

> **مهم:** این رکوردها باید **DNS only (ابر خاکستری)** باشند. اگر از ابر نارنجی استفاده کنید، Cloudflare ترافیک خام TCP را عبور نمی‌دهد و اتصال کلاینت‌ها قطع می‌شود. Reality الزاماً باید مستقیم به سرور برسد.

پس برای همان دامنه یک رکورد جداگانه بسازید:

```
direct.example.com.   A   <IP سرور>   →  DNS only (ابر خاکستری)
```

و در پنل، SNI/Host کانفیگ‌ها را روی `direct.example.com` بگذارید.

## ۵. انتقال کاربران فعلی

اگر از استقرار قبلی کاربر دارید:

1. از پنل قبلی **بکاپ دیتابیس** بگیرید (داخل `.env` مسیر `SQLITE_PATH` مشخص است؛ در استک Docker معمولاً یک volume است).
2. فایل را روی سرور جدید در همان مسیر کپی کنید و مالکیت و سطح دسترسی را با کاربری که کانتینر اجرا می‌کند یکسان کنید:

```bash
docker compose down
cp /tmp/nexus.db /opt/nexus/data/nexus.db
chown -R 999:999 /opt/nexus/data      # uid/gid کانتینر
docker compose up -d
```

3. لینک‌های اشتراک کاربران را به دامنه‌ی جدید به‌روزرسانی کنید (کاربران می‌توانند از پنل، آدرس جدید را بگیرند).

> ساده‌تر: اگر کاربران زیادی ندارید، از همان ابتدا در پنل جدید اکانت بسازید؛ اشتراک‌ها قابل کپی دستی‌اند.

## ۶. نگهداری

```bash
cd /opt/nexus

docker compose logs -f panel      # لاگ‌ها
docker compose restart panel      # ری‌استارت
docker compose pull && docker compose up -d   # به‌روزرسانی پس از pull شدن کد جدید
```

**پشتیبان‌گیری:**

```bash
docker compose exec panel sh -c 'sqlite3 /data/nexus.db ".backup /data/backup.db"' \
  && docker cp /opt/nexus/data/backup.db ~/nexus-backup-$(date +%F).db
```

یک کرون روزانه بگذارید تا هرگز داده‌ای از دست نرود.

## ۷. عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| پنل بالا نمی‌آید | پورت ۸۰۸۰ در ufw یا Security Group باز نیست |
| Reality وصل نمی‌شود | رکورد DNS روی ابر نارنجی است، یا پورت ۸۴۴۳ بسته است |
| MTProto وصل نمی‌شود | اول باید در پنل فعال شود، بعد پورت ۸۴۶ را باز کنید |
| لینک اشتراک دامنه‌ی قبلی را نشان می‌دهد | `PUBLIC_BASE_URL` در `.env` را درست کنید و `docker compose up -d` |
| پنل کند است | رمز ۱ گیگابایتی است؛ پلن ۲ گیگابایتی بگیرید |

لاگ‌ها:

```bash
docker compose logs --tail 100 panel
```
