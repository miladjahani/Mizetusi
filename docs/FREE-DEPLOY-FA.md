# استقرار رایگان NEXUS — روی ماشین خودتان، پشت Cloudflare Tunnel

این راهنما پنل را **با هزینهٔ صفر** بالا می‌آورد: نه پلن پولی، نه کارت بانکی، نه VPS، نه IP عمومی، نه باز کردن پورت روی مودم. تنها چیزی که لازم دارد یک ماشین لینوکسی است که ۲۴/۷ روشن بماند، و یک تونل رایگان کلودفلر که آن را روی دامنهٔ خودتان منتشر می‌کند.

---

## ۰. اول صادقانه: «رایگان» چه چیزی هست و چه چیزی نیست

سه راه رایگان امتحان شد و دو تای اول جواب نمی‌دهند:

| راه | نتیجه |
|---|---|
| **Cloudflare Worker + Container** | ❌ Container فقط روی پلن **Workers Paid** (۵ دلار در ماه) وجود دارد. روی Free، کل build موفق می‌شود و deploy دقیقاً در آخرین ثانیه با `/accounts/<id>/containers/me` می‌ایستد — خطایی که شکل خطای توکن دارد ولی خطای پلن است. |
| **هاست‌های رایگان Docker** (Render، SnapDeploy، Koyeb، Cloud Run) | ❌ همه بعد از بی‌کاری **می‌خوابند** (Render بعد از ۱۵ دقیقه). برای این اپ این کشنده است: Xray داخل همان کانتینر است، پس با خوابرفتن، تونل **همهٔ** کاربران قطع می‌شود، نه فقط پنل. |
| **ماشین خودتان + Cloudflare Tunnel** | ✅ همین راهنما. رایگان، همیشه‌روشن، و پورت خامِ تونل لازم نیست. |

**پس تنها پیش‌نیاز واقعی این است: یک ماشین که ۲۴/۷ روشن بماند.** لپ‌تاپ قدیمی، مینی‌پی‌سی، رزبری‌پای ۴/۵، یا حتی یک VPS که از قبل دارید. حداقل مشخصات: **۱ هسته، ۱ گیگابایت رم، ۲۰ گیگابایت دیسک**.

> اگر چنین ماشینی ندارید، این راهنما برای شما نیست و صادقانه بگویم گزینهٔ رایگانِ همیشه‌روشنِ دیگری وجود ندارد. در آن حالت باید بین «رایگان ولی خواب‌رفتنی» و «همیشه‌روشن ولی چند دلار در ماه» یکی را انتخاب کنید.

---

## ۱. چرا تونل، و نه پورت‌فوروارد

`cloudflared` یک اتصال از **داخل به بیرون** به کلودفلر می‌سازد و باز نگه می‌دارد. نتیجه‌اش:

- **نه IP عمومی لازم است، نه port forwarding، نه تغییر فایروال** — پس یک اتصال خانگی پشت NAT هم ماشین معتبری است.
- **آدرس عمومی، دامنهٔ خودتان است** — زیردامنه‌ای از دامنه‌ای که در کلودفلر دارید. پس کاربر داخل ایران IP تمیز کلودفلر را می‌بیند، نه IP ماشین شما. (پسوند `*.workers.dev` که در ایران فیلتر است اصلاً اینجا مطرح نیست.)
- **رایگان است** — نه پلنی برای خرید، نه کارتی برای وارد کردن، و پهنای باند تونل هم محدودیت پلن رایگان را ندارد.

---

## ۲. دامنه

یک دامنهٔ ارزان (سالانه چند دلار) لازم دارید که در کلودفلر باشد:

1. دامنه را بخرید و در Cloudflare Dashboard → **Add a site** اضافه کنید.
2. نیم‌سرورهای کلودفلر را روی دامنه تنظیم کنید.

> اگر دامنه ندارید، این تنها هزینهٔ این راهنماست — و تونل بدون دامنهٔ اختصاصی معنا ندارد، چون آدرس تصادفی `trycloudflare.com` در ایران فیلتر است.

---

## ۳. ساخت تونل و گرفتن توکن

1. Cloudflare Dashboard → **Zero Trust** → **Networks** → **Tunnels** → **Create a tunnel**.
2. نوع **Cloudflared** را انتخاب کنید و یک نام بدهید (مثلاً `nexus`).
3. صفحهٔ بعد **توکن** را نشان می‌دهد (رشتهٔ بلندی که با `eyJ...` شروع می‌شود). کپی کنید — همین توکن تمام احراز هویت است.
4. در همان صفحه، تب **Public Hostname** → **Add a public hostname**:

   | خانه | مقدار |
   |---|---|
   | Subdomain | `panel` |
   | Domain | دامنهٔ خودتان |
   | Type | `HTTP` |
   | URL | **`nexus:8080`** |

   > ⚠️ در خانهٔ URL باید **`nexus:8080`** بنویسید، نه `localhost:8080`. `nexus` نام سرویس در `docker-compose.yml` است و cloudflared آن را روی شبکهٔ داخلی compose پیدا می‌کند؛ `localhost` داخل کانتینر خودِ cloudflared است و جواب نمی‌دهد.

---

## ۴. اجرای پنل روی ماشین

روی ماشین لینوکسی (به‌عنوان root یا با sudo):

```bash
sudo bash scripts/install-vps.sh --tunnel '<TOKEN>' --domain panel.example.com
```

اگر مخزن را هنوز ندارید:

```bash
curl -fsSL https://raw.githubusercontent.com/miladjahani/Mizetusi/main/scripts/install-vps.sh | sudo bash -s -- --tunnel '<TOKEN>' --domain panel.example.com
```

این دستور کارها را انجام می‌دهد:

1. Docker و compose را نصب می‌کند؛
2. مخزن را می‌گیرد (یا از checkout موجود استفاده می‌کند)؛
3. یک `.env` با `ADMIN_PASSWORD` و `JWT_SECRET` تولیدشده می‌سازد و **توکن تونل و `NEXUS_PLATFORM=tunnel`** را هم در همان می‌نویسد (`chmod 600`)؛
4. استک را با پروفایل `tunnel` بالا می‌آورد — یعنی سرویس `cloudflared` هم شروع می‌شود.

> `NEXUS_PLATFORM=tunnel` صرفاً یک برچسب نیست: به پنل می‌گوید این ماشین پورت خام قابل‌دسترس ندارد، پس **به‌جای دادن لینک مرده، ترنسپورت‌های پورت‌دار را منتشر نمی‌کند** (بخش ۶).

---

## ۵. ورود

`https://panel.example.com/admin` را باز کنید و با `ADMIN_PASSWORD` که اسکریپت چاپ کرده وارد شوید. **بلافاصله رمز را از داخل پنل عوض کنید.** بعد در تب **کلودفلر** همان دامنه را ذخیره کنید و **«پینگ همه نودها»** را بزنید تا لینک‌های سابسکریپشن روی دامنهٔ درست ساخته شوند.

---

## ۶. چه چیزی کار می‌کند و چه چیزی نه

یک تونل فقط **HTTP/HTTPS و WebSocket** را عبور می‌دهد — پورت TCP خام و UDP را نه. پس:

| قابلیت | وضعیت | چرا |
|---|---|---|
| پنل (صفحه‌ها، API، ورود) | ✅ | از تونل رد می‌شود |
| لینک سابسکریپشن و صفحهٔ وضعیت | ✅ | همان |
| VLESS / VMess / Trojan / Shadowsocks / WARP روی WS | ✅ | WebSocket |
| پروکسی WEB تلگرام (`tg://webproxy`) | ✅ | همان دامنه، روی HTTPS |
| Reality و ترنسپورت‌های پیشرفته (gRPC/XHTTP/HTTPUpgrade) | ❌ | پورت TCP خام لازم دارند |
| AnyTLS، TUIC (UDP)، MTProto (`tg://proxy`) | ❌ | پورت خام / UDP |
| پروکسی وب HTTP و SOCKS5 | ❌ | پورت TCP خام |

این دقیقاً همان مجموعهٔ قابلیتِ مسیر Container است — و پنل خودش می‌داند: در بخش «سیستم» مینویسد `Cloudflare Tunnel (self-hosted)` و آن کارت‌ها را با توضیح نشان می‌دهد، نه با لینک.

**اگر ماشین شما IP عمومی دارد** (مثلاً یک VPS که از قبل دارید) و پورت‌ها را هم باز کرده‌اید، می‌توانید پورت خام را هم فعال کنید:

```bash
NEXUS_DIRECT_HOST=<IP عمومی>
NEXUS_DIRECT_PORT=8443
```

با این دو، Reality هم منتشر می‌شود. روی یک اتصال خانگی این کار فایده ندارد، چون پورتی برای فوروارد وجود ندارد.

## ۸. عیب‌یابی

| نشانه | دلیل | راه‌حل |
|---|---|---|
| کلودفلر `502` یا خطای `1033` می‌دهد | اپ بالا نیامده، یا URL سرویس غلط است | `docker compose logs -f nexus`؛ در Public Hostname باید `nexus:8080` باشد نه `localhost:8080` |
| سرویس `tunnel` مدام restart می‌شود | توکن غلط یا منقضی | توکن را از Zero Trust → Tunnels دوباره کپی کنید و در `.env` جای `CLOUDFLARE_TUNNEL_TOKEN` بگذارید |
| پنل می‌گوید «آی‌پی عمومی قابل‌اتکا پیدا نشد» | طبیعی است | همین رفتار درست است: پشت NAT پورت خامی وجود ندارد. برای Reality بخش ۶ |
| `/health` می‌گوید `ok:false` | `NEXUS_ORIGIN` ست نشده و Container هم بایند نشده | این مسیر به آن کاری ندارد؛ استک را بالا بیاورید: `docker compose ps` |
| بعد از ری‌استارت ماشین همه‌چیز پایین است | `restart: unless-stopped` کار نکرده | `sudo systemctl enable --now docker` تا Docker با بوت بالا بیاید |
| پنل از شبکهٔ داخلی هم باز است | پورت‌های compose روی LAN منتشر می‌شوند | در `docker-compose.yml` خط `'8080:8080'` را به `'127.0.0.1:8080:8080'` عوض کنید و `docker compose up -d` |
| کاربران با VPN وصل می‌شوند ولی بدون آن نه | دامنه روی پروکسی کلودفلر نیست | در Cloudflare، رکورد دامنه باید **Proxied** (ابر نارنجی) باشد |
